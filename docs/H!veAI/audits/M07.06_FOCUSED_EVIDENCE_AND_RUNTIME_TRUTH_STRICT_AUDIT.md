### C06 SQLite durability — FAIL / MAJOR

Positive improvements:

- logical `rusqlite::backup` is used;
- repeated backup and `.bak.prev` retention are now tested;
- per-connection FK/WAL/busy-timeout and healthy quick-check are partly tested.

Remaining evidence gaps:

- backup publication failure preserves source and prior good backup;
- bounded busy/locked contention;
- corrupted DB initialization preserves the original corrupt source bytes;
- backup failure prevents migration mutation;
- synchronous policy is not asserted in the new per-connection test.

More importantly, `DatabaseState::initialize()` currently opens the normal read-write database and calls `configure_connection()` **before** `PRAGMA quick_check(1)`. `configure_connection()` attempts `journal_mode=WAL` before corruption is accepted as healthy. Therefore the contract "corrupted DB initialization fails without changing corrupt source bytes" is not guaranteed by construction. Existing databases must be preflight-integrity-checked without write-affecting pragmas before normal WAL configuration/migration work.
