# M08.00 Manual Acceptance Failure Addendum 2

Date: 2026-08-25

## Status

`M08.00 MANUAL ACCEPTANCE = FAIL`

This addendum records a more precise native-startup observation made before the user executed the M08.00B remediation prompt.

## New user evidence

On cold launch, H!veAI does not simply skip the opening-video lifecycle. Instead, for approximately the video duration (about 8 seconds), the normal dashboard remains visible while the window gains both horizontal and vertical scrollbars. The user can scroll/pan this oversized temporary first state. After approximately 8 seconds, the temporary overflow disappears and the normal dashboard returns.

This means the intro component is being mounted for roughly the expected media duration, but it is not behaving as a true fixed full-window overlay.

## Source-level diagnosis

`StartupIntro.tsx` renders a sibling `<div className="startup-intro">` after `<App />`, containing the opening `<video>`. The current production stylesheet does not define a matching `.startup-intro` / `.startup-intro-closing` fixed-overlay treatment.

Therefore the intro element participates in normal document flow instead of covering the viewport. Because `<App />` already occupies the application viewport, the additional video container can extend the document beyond the viewport and create temporary horizontal/vertical scrollbars. When the video reaches `ended` and `StartupIntro` unmounts, the overflow disappears, matching the user's native observation.

This refines the previous F02 finding. The bundled video is likely being mounted/played, but the missing overlay CSS prevents the user from seeing the intended fullscreen intro.

## Required remediation impact

M08.00B must therefore fix all of the following before acceptance:

1. move the canonical hive background canvas so it begins after the left sidebar and centers in the post-sidebar workspace;
2. make startup/restart intro ownership deterministic for the native lifecycle;
3. add explicit fixed fullscreen intro CSS so the opening video is actually visible above the app and never participates in normal layout flow;
4. prove that no temporary horizontal or vertical document scrollbars are created while the intro is active;
5. keep `<App />` mounted behind the overlay and preserve `hiveai_frontend_ready` independence;
6. keep the intro inside the existing Tauri window with no external player/browser/terminal.

## Manual acceptance additions

The next native build must additionally prove:

- during the intro, only the opening video/black intro surface is visible, not an oversized scrollable dashboard state;
- no horizontal scrollbar appears;
- no vertical scrollbar appears because of the intro;
- the intro covers the entire H!veAI client viewport with a fixed overlay;
- after `ended` + fade, the normal dashboard appears without geometry shift.

M08 Task Source Discovery remains blocked until M08.00B passes independent audit and user acceptance.
