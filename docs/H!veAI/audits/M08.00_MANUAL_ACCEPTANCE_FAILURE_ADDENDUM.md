## User-observed failures

### F01 — Global background is centered against the full application window instead of the post-sidebar workspace

The canonical hive/bee image is visibly rendered beneath the left navigation/sidebar because production CSS attaches the background to `.app-shell::before`.

The user requires:

- the left navigation/sidebar must remain outside the canonical background image;
- the background image must begin exactly at the right edge of the left navigation/sidebar;
- the hive and bee composition must be centered within the remaining main workspace area, not centered within the full application window including the sidebar;
- the same post-sidebar positioning must remain stable across Command Center, Projects, Tasks, Agents, Audit Center, Activity, Settings, and project cockpit routes;
- no layout width, sidebar width, approved logo sizing, or Command Center geometry may change merely to reposition the background.

Repository source confirming the cause:

```css
.app-shell::before {
  ...
  background: ... url("./assets/hiveai-app-background.png") center center/cover no-repeat;
  ...
}
```

Because `.app-shell` includes both sidebar and main area, `center center` currently centers the art across the whole app rather than the workspace to the right of navigation.

### F02 — Native opening video does not play on application launch

The user launched the republished desktop build from `Desktop\H!veAI.lnk` and the application opened directly to the UI. No startup video appeared.

The current implementation uses a frontend `sessionStorage` guard:

`hiveai.startup-intro.played`

The earlier audit explicitly left real WebView2/Tauri session semantics unverified. Real user evidence now shows the current lifecycle gating is not acceptable for the required cold-launch behavior.

Required behavior remains:

- cold native application launch => opening video plays exactly once;
- normal SPA route navigation => no replay;
- project selection => no replay;
- minimize/restore => no replay;
- Settings -> Restart H!veAI -> native restart => video plays exactly once again;
- media failure => app remains usable;
- no browser, terminal, external player, or second Tauri window.
