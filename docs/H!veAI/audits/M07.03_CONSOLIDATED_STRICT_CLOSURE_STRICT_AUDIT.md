## 5. FILE / SYMBOL EVIDENCE

### BLOCKER M07.03-B01 — watcher explicit rescan still lies about recovery

`src-tauri/src/watcher.rs::refresh_project_snapshot` persists the project snapshot using the current `rescan_required` value, then later executes:

```rust
if explicit {
    status.rescan_required = false;
}
```

This clear is not gated on `available == true` or on a separately defined successful reconciliation result. Therefore a missing root can still have its in-memory rescan-required flag cleared, and the persisted row can disagree with final in-memory state.

### BLOCKER M07.03-B02 — non-Git -> Git repair bypass remains

`insert_repository` returns without writing a row for non-Git projects. `repair_project_path` reads previous identity only from `repositories`. Thus a registered non-Git project has `existing_identity = None` and bypasses the type-change check when repaired to an unrelated Git folder.

### MAJOR M07.03-M01 — no-remote identity does not use ancestry

When no remote exists, the Registry rejects if `old_head != git.head_sha`. The required policy allowed continuity when the stored old HEAD exists in the replacement repository and is an ancestor of the new HEAD. No such fixed read-only ancestry check is implemented.

### MAJOR M07.03-M02 — migration v6 misses known legacy field

`RESIDUAL_TIMESTAMP_STANDARDIZATION` does not update `project_snapshots.created_at`, even though this field is a known M07-era epoch-string candidate explicitly named in the M07.03 acceptance contract.

Because the user's local QA DB may already have applied schema v6, do not repair this solely by editing v6. A new migration is required.

### MAJOR M07.03-M03 — SQLite backup repeated/failure behavior incomplete

The SQLite-native backup is an improvement, but the stable backup is published with `fs::rename(temp, backup)` without a tested replacement/rotation strategy for an already-existing backup on Windows. Required repeated-backup, lock/busy, corruption and backup-failure source-integrity tests are absent.

### MAJOR M07.03-M04 — binary-diff product boundary not proven

`sanitize_binary_payloads` exists and bounding happens after sanitation. However:

- required real `diff()` tests through a registered temporary project/database are absent;
- the old raw-Git binary test remains;
- when a fallback raw payload contains `GIT binary patch`, the current metadata collector can add every `diff --git` path from the raw diff to `binary_files`, potentially misclassifying text files in a mixed diff.

### MAJOR M07.03-M05 — launcher provenance bypass and failure cleanup

`publish-dev-qa.ps1` has `-SkipBuild`. With that switch it accepts the default target/release candidate after PE validation without structural proof that the current candidate was produced by the helper's Tauri no-bundle build. The Codex log itself reports using `-SkipBuild` for final publication.

Candidate smoke does not positively prove the embedded React/Tauri frontend mounted; window title alone can exist while a WebView error page is displayed. Failure before the normal close path can also leave the candidate process alive because cleanup is not enforced in every exception path.
