## Startup architecture

`src/main.tsx` still mounts `FrontendReady`, which renders `<App />`
immediately and renders `<StartupIntro />` as a sibling overlay. The existing
post-mount `invoke("hiveai_frontend_ready")` effect remains independent of
video playback.

`src/components/StartupIntro.tsx` uses the native Tauri boundary
(`isTauriDesktop`) and a `sessionStorage` key
`hiveai.startup-intro.played`. This prevents replay during route changes,
project selection, remounts, minimize/restore, and ordinary in-app navigation.
A full native restart creates a new WebView/session lifecycle, so the intro can
play once again.

Video behavior:

- `autoplay`: enabled
- `muted`: enabled
- `playsInline`: enabled
- `loop`: absent/false
- `controls`: false
- `preload`: `auto`
- natural `ended` event starts the fade-out
- fade duration: `280ms`
- media error or `15,000ms` bounded failsafe dismisses the overlay
- `object-fit: contain` and deep navy full-window treatment are defined by
  `startup-intro` CSS
- no browser/player window, terminal, or second Tauri window
