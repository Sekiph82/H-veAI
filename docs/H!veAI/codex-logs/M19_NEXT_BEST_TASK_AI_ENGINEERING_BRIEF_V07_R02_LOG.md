## Production-path changes

- `SchedulerLifecycleState` is shared by the real polling loop and native tests. It owns worker admission, per-project in-flight identity, pending refresh attachment, exact result matching, and late-result rejection.
- Worker jobs/results carry `ObservationIdentity { observation_id, project_id, started_epoch }`. A stale, timed-out, or unrelated result cannot complete a generation or authorize M19 history recording.
- Worker capacity is `4`; scheduler tick is `1s`; manual admission budget is `81s` (the `80s` execution budget plus one scheduler tick); manual execution remains bounded to `80s`.
- Pending manual requests are prioritized at admission without broadening their project scope. Same-project requests coalesce only when they attach to the same qualifying observation; A/B scopes remain independent.
- Successful changed-HEAD observations set `validated_at` at completion, and next due is derived from that same completed observation boundary. Failed changed-HEAD validation preserves the previous validation boundary and fails closed.
- Legacy snapshots without a materialized `validated_at` are not treated as fresh. Remote failure never becomes a fresh success or permits a false history transition.
