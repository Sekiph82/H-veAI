## Section 1: SQLite corruption-safe preflight

### Production change

`DatabaseState::initialize()` now opens a read-only preflight connection on existing non-empty databases and runs `PRAGMA quick_check(1)` before the normal WAL/FK connection configuration. Fresh databases skip the preflight. The normal connection is only opened after the preflight passes.

### Focused tests added

- `sqlite_corrupt_db_preflight_fails_without_changing_source_bytes` — writes corrupt bytes, verifies init fails, verifies original bytes unchanged.
- `sqlite_busy_locked_contention_respects_configured_bounds` — holds exclusive lock, verifies busy timeout behavior.
- `sqlite_backup_publication_failure_preserves_source_and_prior_backup` — simulates rename failure via read-only directory, verifies source and prior backup intact.
- `sqlite_backup_failure_prevents_migration_mutation` — verifies that if backup fails, migration never runs on the source database.
- `sqlite_open_connection_reports_fk_wal_busy_timeout_and_synchronous` — verifies all four connection policies on every `open_connection()` call.

All tests hit production `DatabaseState` functions.
