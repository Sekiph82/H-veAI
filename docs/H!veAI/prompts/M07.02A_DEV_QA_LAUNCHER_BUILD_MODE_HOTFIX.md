## BLOCKER — Current stable dev executable is the wrong build mode

The stable manual-QA executable MUST NOT depend on the Vite dev server at `127.0.0.1:5173`.

The current user evidence proves the published executable is behaving as a development-mode binary: with no Vite dev server running, the H!veAI webview navigates to `127.0.0.1` and fails.

### Required correction

1. Build the manual-QA desktop executable through the Tauri CLI production build path, not by publishing a raw `cargo build` / `cargo build --release` artifact whose runtime still resolves `build.devUrl`.
2. Use the Tauri 2 production frontend embedding path (`build.frontendDist`) and run the configured `beforeBuildCommand`.
3. For active development, build without creating an installer/bundle. Preferred command from `H!veAI`:

```powershell
npm run tauri:build -- --no-bundle
```

Equivalent `cargo tauri build --no-bundle` is acceptable only if it resolves the same project/config and produces the same verified production-mode executable.
4. Do NOT run `tauri dev` for the stable manual-QA executable.
5. Do NOT require Vite, npm dev server, localhost, `127.0.0.1:5173`, or WebSocket dev origins at runtime.
6. Publish the validated Tauri production-mode binary to the existing stable path:

`C:\Users\sekip\Desktop\AI-Commerce-HQ files\AI-Commerce-HQ\H!veAI\dev-bin\H!veAI.exe`

7. Keep `Desktop\H!veAI.lnk` targeting that exact stable executable.
8. Keep the shortcut icon derived from the canonical `H!veAI small logo.png` source.
9. No Windows installer may be created or invoked.

## BLOCKER — No console window for normal QA launch

The current screenshot also shows a visible console window carrying H!veAI log output. The normal GUI executable must not require or leave a console window visible.

Add the conventional Windows release-subsystem attribute to the binary entry point as appropriate for this Tauri app, e.g. in `src-tauri/src/main.rs`:

```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]
```

Preserve normal file/plugin logging. Hiding the console must not suppress application logs written through the configured logging layer.

## Browser / WebView policy clarification

H!veAI is a Tauri desktop application. Its application shell must render inside the Tauri window.

- Do NOT launch Microsoft Edge for the H!veAI application shell.
- Do NOT launch Google Chrome for the H!veAI application shell either.
- On Windows, Tauri may internally use Microsoft WebView2 as its embedded rendering engine. That is acceptable and is not the same thing as opening the Microsoft Edge browser.
- The user preference for Google Chrome applies only when H!veAI intentionally opens an external web URL/file in a standalone browser.
- For such external navigation, prefer Google Chrome and do not silently fall back to Edge if Chrome is unavailable.
