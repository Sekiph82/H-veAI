# R01 — BLOCKER — EXPLICIT RESCAN STATE MACHINE AND PERSISTENCE AGREEMENT

Origin: `M07.03-B01`

Primary file:

`H!veAI/src-tauri/src/watcher.rs`

Relevant symbols:

- `WatcherManager::rescan_project`
- `refresh_project_snapshot`
- project snapshot persistence
- watcher status update

## Current incorrect behavior

The current implementation persists a project snapshot with the pre-clear `rescan_required` state and afterward performs an unconditional in-memory clear for `explicit == true`:

```rust
if explicit {
    status.rescan_required = false;
}
```

This permits a missing/unavailable explicit rescan to lie about recovery and can make DB state disagree with in-memory state.

## Required target behavior

Define explicit rescan success as a real reconciliation outcome, not merely `explicit=true`.

A successful explicit rescan may clear `rescan_required` only if ALL required reconciliation steps succeed, including:

1. registered project exists;
2. project root is available and valid;
3. watcher/repository evidence required for that project is reconciled successfully;
4. Git refresh, when applicable, succeeds;
5. final project snapshot persistence succeeds;
6. the persisted final state is the same state exposed in memory.

If any step fails:

- preserve `rescan_required=true` when it was already required;
- return a structured error or explicit degraded result;
- do not report recovered/healthy state;
- do not write a persisted row claiming a final state different from memory.

Ordinary event refresh must never clear a required rescan.

## Preferred implementation shape

Compute a single **final desired watcher state** first and persist that same final state before publishing it to in-memory status, or use a transaction/sequence that guarantees DB and memory agree after success.

Do not persist one state and then mutate memory to a different state.

## Required direct tests

Use isolated temp DB/project fixtures and production functions:

2. ordinary refresh -> remains true;
3. successful explicit rescan on available project -> false;

5. missing-root explicit rescan -> remains true;
6. newest persisted state after missing-root attempt does not falsely report recovery;
7. forced Git refresh failure for Git project -> remains true;
8. forced persistence/reconciliation failure -> remains true;
9. persisted and in-memory state agree after all successful/failing paths;
