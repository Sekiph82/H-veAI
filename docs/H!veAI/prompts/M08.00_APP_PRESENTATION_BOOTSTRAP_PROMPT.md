# R04 — Play-once semantics within one app lifecycle

Use a robust frontend-lifecycle guard so the intro plays once for a given application window/session and does not replay because React route content changes.

A session-scoped/in-memory guard is acceptable. `sessionStorage` may be used if it is proven to behave correctly in the Tauri WebView for:

- cold app launch => intro plays;
- SPA navigation => intro does not replay;
- same-window frontend reload => ideally does not replay;
- full Tauri native restart => intro plays again.

Do not use `localStorage` as the sole play guard because it can persist across full application restarts and suppress the required restart playback.

Do not couple intro playback to route pathname.

If Tauri/WebView session semantics do not reliably distinguish native restart from ordinary reload, use the smallest native/frontend lifecycle mechanism needed to make the behavior deterministic. Do not create a broad new runtime subsystem.

The existing Settings restart command itself should remain unchanged unless direct evidence proves a lifecycle integration bug.

# R05 — H!veAI Neon Liquid Glass adaptation

Adapt the FMCG ERP `NEON LIQUID GLASS DESIGN SYSTEM` into H!veAI without redesigning the application.

The new hive background should remain subtly visible behind selected UI surfaces, while operational content remains highly readable.

## Visual character

Target:

- dark translucent navy glass;
- subtle backdrop blur and saturation;
- thin cyan/blue borders;
- restrained violet secondary glow;
- faint white inset highlight;
- slightly stronger glow on hover/focus;
- premium AI engineering command-center feel.

Avoid:

- cartoon neon;
- excessive bloom;
- continuous pulsing;
- gaming-HUD styling;
- making every surface transparent;
- readability loss.

## Design tokens

Use the FMCG system as reference for effect character and adapt into the existing H!veAI token system. Reference values include:

```css
--glass-bg: rgba(15, 23, 42, 0.58);
--glass-bg-strong: rgba(15, 23, 42, 0.78);
--glass-border: rgba(96, 165, 250, 0.28);
--glass-border-strong: rgba(139, 92, 246, 0.48);
--glow-cyan: 34, 211, 238;
--glow-blue: 59, 130, 246;
--glow-indigo: 99, 102, 241;
--glow-purple: 139, 92, 246;
--glow-pink: 217, 70, 239;
```

Do not introduce a separate competing theme. Fold equivalent tokens into H!veAI `:root` cleanly.

## Buttons

Adapt the existing H!veAI primary and secondary button classes instead of creating disconnected one-off styles.

Primary buttons:

- cyan/blue/indigo/violet gradient character;
- translucent glass support;
- thin bright border;
- controlled glow;
- faint inset highlight;
- hover may brighten and move at most `translateY(-1px)`;
- focus-visible must remain obvious and accessible.

Secondary buttons:

- dark translucent navy glass;
- gentler cyan/blue border/glow;
- stronger but restrained hover/focus treatment;
- no strong permanent gradient unless already semantically appropriate.

Preserve:

- existing dimensions/layout contracts;
- accessible labels;
- disabled semantics;
- keyboard focus visibility;
- no bounce;
- no persistent animation loop.

## Tables

Apply glass treatment to all **real existing table surfaces** in H!veAI.

Do not fabricate tables on routes that do not currently use them.

Table shell:

- translucent dark navy glass;
- `backdrop-filter` blur/saturation;
- thin cyan/blue border;
- restrained blue/violet shadow;
- faint inset highlight.

Table header:

- darker translucent navy layer;
- thin cyan/blue separator;
- restrained cyan/blue header text;
- preserve current typography scale.

Rows:

- low-opacity separators;
- no movement;
- hover uses a very light transparent blue fill;
- selected/active row preserves existing semantic state and adds only a restrained border/glow accent.

## Panels / cards

Only where necessary for the background to read through, reduce opacity of selected shared panels/cards enough to create subtle glass depth.

Do not turn every panel into a bright transparent tile.

Critical Command Center information must remain readable at a glance.

## Performance

Backdrop filters and layered shadows must remain bounded for Tauri/WebView2:

- avoid heavy blur on dozens of nested children;
- prefer shared container glass surfaces;
- no animated blur;
- no continuous box-shadow pulsing;
- no canvas/WebGL glass effects;
- no layout-jank on hover;
- preserve smooth scroll/interaction;
- respect reduced-motion behavior for transform-heavy hover effects.
